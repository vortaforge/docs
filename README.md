# vortaforge/docs

Complete documentation for VortaForge.

Everything in one place: the two live Fabric mods, the archived and disarmed
datapacks, the gate that was removed and the warning that replaced it, plus
references for the API, the version matrix and the rules a maintainer follows.

## Two ways this is published

| Target | What it is | Why |
|---|---|---|
| **The PHP site** | `pages/**/*.php`, served by any PHP 8.1+ host | The pages are scripts; the shell exists once |
| **The static snapshot** | `build/`, generated by `tools/render_pages.php --out=build` | GitHub Pages cannot execute PHP |

Both come from the same source. The snapshot is rendered from the pages, so it
cannot drift from them, and a page that fails to render fails the build rather
than a visitor.

## Layout

```
pages/                  the site - one PHP script per page
assets/style.css        the stylesheet, inlined at render time
tools/sitelib.php       the shell: nav, stylesheet, footer, vf_render()
tools/cli.php           guard: 404 on web, PHP 8.1 floor
tools/render_pages.php  render all pages; write the static snapshot
tools/build_docs_index.php  _site/docs-index.json
tools/test_php_safety.php   the bans and the rules
build/                  generated static snapshot (not committed)
```

## Running it

```sh
php -S localhost:8000 -t pages     # or any PHP 8.1+ host pointed at pages/
php tools/render_pages.php         # render all 15 pages, fail on any error
php tools/test_php_safety.php      # the bans, the CLI guards, the page rules
php tools/build_docs_index.php     # _site/docs-index.json
php tools/render_pages.php --out=build   # the static snapshot
```

## Editing

Every page is a PHP script under `pages/`, served at the path it sits at. A page
sets four variables and writes its body; the shell around it - doctype, head,
navigation, footer, inline stylesheet - lives once in `tools/sitelib.php`.

```php
require_once __DIR__ . '/../../tools/sitelib.php';

$section = "docs";  $file = "api.php";
$title   = "API";   $description = "…";
$crumbs  = '<a href="../index.php">Home</a> / API';

ob_start(); ?>
  <h2>…</h2>
<?php $body = ob_get_clean();

vf_render($section, $file, $title, $description, $body, $crumbs);
```

The stylesheet is still inlined per page rather than linked, because a page has
to render with no network access at all. It is read from `assets/style.css` at
render time, so there is one copy, not fifteen.

## What keeps it honest

| Rule | Enforced by |
|---|---|
| No `eval`, no shell, no request input anywhere | `tools/test_php_safety.php` |
| Build scripts refuse a web SAPI | `tools/cli.php`, required by each |
| Pages never read `$_GET`/`$_POST`/`$_SERVER` | `tools/test_php_safety.php` |
| Every page renders, with the stylesheet and nav | `tools/render_pages.php` |
| Every page is indexed | `tools/build_docs_index.php` |

## Why the warning links here

The in-game warnings added to the archived datapacks link to
`docs/warnings.php` on this site. A warning that points at a dead URL is worse
than no warning, so the link target is a stable path with no redirect behind it.
