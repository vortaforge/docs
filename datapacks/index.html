Datapacks

Twelve datapacks, all archived. What they were, what they ran on, and the one that was rebuilt as Fabric mods.

Every pack on this page is archived and disarmed. Nothing here is maintained, supported or recommended for a live server. They are kept as readable history. See warnings for what "archived and disarmed" actually means in a world.

Why they were retired

A datapack was the wrong delivery format for what these did, and the archive records the reasons rather than a summary. The same four problems recur in every entry:

No type safety

Every value crossing a function call, a storage read, a scoreboard comparison or a macro expansion is an untyped string. Nothing validates it at load time or at run time, so a typo fails silently or, worse, succeeds with the wrong meaning.

No enforcement boundary

Dynamic command execution runs at function-permission-level with no authentication boundary around it. A datapack is plain text that the server reads; anything it "gates" can be deleted by editing a file.

No tooling

No debugger, no inspection, no error surface. A function that silently returns early looks exactly like a function that succeeded.

No warning surface

The pack cannot tell a player it is abandoned. That had to be added afterwards, as a generated function wired into the load tag.

What each one was

macroEngine-Datapack-v26.3

A command engine: dispatch, deferred queue, state, config, permissions, and 1,280 functions across the areas listed in the macroEngine section. This is the only pack on this page with a successor - it was split into a core and 33 modules and repackaged as Fabric mods, which is what the module list documents. The datapack itself is still here, archived, because the mod layout is a different project and the original should stay readable.

RTWrapper v1.0.1 and RTWrapper

Two entries. RTWrapper-v1.0.1 is the datapack at format 121.0. RTWrapper is the container: a nested datapack at format 107.1 plus a Fabric implementation that was retired. Both carry the same 700-function command wrapper surface, and both had the gate layer that was removed from the tree in the same change as macroEngine's.

The five older packs

TunnelScript (1.19.2, format 10), cmdTunnel-datapack (1.19.3-1.19.4, format 12), vf_macro (1.16-1.20, format 6), InteractionClickDetection (1.20.x, format 26) and LeftClickDetection (1.20.5-1.21.x, format 41). These predate the 26.x format entirely, which is why their pack formats are single numbers. They will not load on a 26.3 server without being rewritten.

DailyBonus, QuickShare, guikitfw

All three target 26.x at format 121.0: a once-per-in-game-day login reward, a per-player item sharing helper, and a storage-authored GUI framework that drives a chest minecart as its runtime. guikitfw is the largest of the three at 192 functions.

If you want to read one

They are ordinary folder trees under archived/packs/ in the core repository. Nothing needs to be built. To inspect one without running it, read data/<namespace>/function/; the load order is whatever the #minecraft:load tag names.

Do not install one on a server you care about. Not because they are malicious, but because they are unfinished: they were abandoned mid-development, the security model they assumed does not exist, and no one has run them against a modern server. The archive entry for each says the same thing in more detail.
