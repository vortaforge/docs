Warnings

What the notice on an archived pack means, what "disarmed" means, and why there is no longer anything stopping you from loading one.

1. What you clicked

An archived project's page carries a notice. It says the project is retired, names the last version that worked and points at whatever replaced it, if anything did. It is generated from archived/archive.json, so it cannot drift from the archive table on the archive page.

The notice exists because a retired pack looks identical to a live one from the outside. Same jar, same pack.mcmeta, same function ids. The only difference is that nobody has tested it against the release you are running.

2. What "disarmed" means

Disarmed means the project is excluded from the build. It is still in the repository, still readable, still historically accurate - but settings.gradle does not scan archived/, so it never becomes a subproject and never produces an artifact.

// settings.gradle, verbatim
// 'archived/' is deliberately NOT a scan root: everything there is disarmed
// (see archived/archive.json) and must never become a buildable subproject
// again.
def SCAN_ROOTS = ['mods', 'packs', 'examples']

That is a stronger claim than "we do not build it". It means an archived pack cannot re-enter a release by accident: no glob picks it up, no gradlew dist emits it, and the archive JSON is the only place that knows it exists.

3. Gates, and why they were removed

What a gate was

A gate was a runtime check inside the engine that refused to work until a condition was met. Two existed:

GateWhereWhat it did
In-pack load gatemacroengine:gate/is_open Aborted the engine's own load if the pack had not been acknowledged.
Repository guardthe build Refused to package a retired pack unless an override was set.

Why both went

A gate is a defect, not a safeguard. Three reasons, in the order they became obvious:

  1. It blocked the wrong person. Someone running an archived pack inside their own world was stopped by a check they had no way to satisfy. Someone determined to run it deleted one line.
  2. It failed in the dark. A gated pack did not crash; it loaded and then did nothing, which looks exactly like a broken install. The failure mode was worse than the thing it prevented.
  3. It cost the modules. Every module had to prove it was allowed to run, which meant every module carried the gate's assumptions. Removing the gate removed that dependency from 34 packs at once.

The id macroengine:gate/is_open no longer resolves. If you are reading an old function that calls it, delete the call - nothing replaces it, because nothing needs to.

A warning is not a gate. It never was. A warning tells the truth about a pack's status; a gate refused to run it. The warning survived because it is information. The gate did not, because it was enforcement with a bypass and no upside.

4. Why some packs cannot show the warning

The warning is a function wired into the load tag. Packs that predate that wiring - anything written before the warning existed, and packs whose own load path never runs - have no way to display it.

Two cases in the archive:

  • Older packs (pack format 6–41). Written before the load hook existed. They work or they do not; there is nothing to hook.
  • Packs with no load function at all. A pack that only defines tags for other packs to call has no entry point of its own, so there is nowhere to mount a message.

This is a limitation of where the message can be attached, not a statement about those packs being safer. If a pack cannot warn you, that is the reason to read the archive instead.

5. If you still want to run a pack

Reasonable - the archived packs are small, readable, and some of them still work. Do these four things:

  1. Back up the world first. Not because the pack is malicious; because the first symptom of a version mismatch is often a half-applied change to a scoreboard objective.
  2. Check the pack format. Compare the format column on Versions with the one your server reads. A mismatch is the single most common reason an old pack does nothing.
  3. Read its load function. If it sets objectives, restore them before you remove the pack, or the objective stays and the values stop updating.
  4. Do not run it next to macroEngine. Both may claim the same scoreboard holders. The engine's are documented; an old pack's are not.

6. What a warning is not

It is not an audit. It does not say the pack is safe to run, and it never gated anything. It says the pack is retired - which is a fact about maintenance, not about behaviour.

That distinction is the whole point of removing the gates. A warning you can ignore and a gate you cannot were being confused for each other, and the gate was making the confusion worse by pretending to be a safety feature.
