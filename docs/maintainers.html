The repository guard

The guard used to be a build step that refused to package a retired pack unless an environment variable was set. It is gone, and the job moved to the build layout instead:

def SCAN_ROOTS = ['mods', 'packs', 'examples']

archived/ is not a scan root, so nothing underneath it can become a subproject. That is not a check that can be bypassed with a flag - there is no code path from archived/ to gradlew dist at all. Removing the environment variable removed the bypass, not the protection.

Archive rules

RuleWhy
A retired project gets a row in archived/archive.json. Nineteen fields, so a question six months later has an answer without a forensic walk through git.
Its reason names what happened, not that it was bad. "A Fabric mod superseded it" is checkable. "It was old" is not.
Its original_path is recorded if it moved. The move is the interesting part - it usually explains the retirement.
The row is never deleted. Deleting it removes the only evidence the thing existed.
Provenance prose and history files are not rewritten. An identifier change (a package rename, a namespace move) must not touch CREDITS-style text. That text is the record of what was.
A patch series must still apply. If archived/patches/*.patch stops applying, the record of how a change was made is gone.

The rule that outranks the others

Move identifiers, never history. When a namespace changes - vortacraftmc becoming vortaforge, say - code, paths, package names and scoreboard holders move. Comments, credits, changelog text and patches do not. A rename that also rewrites the past makes the past unverifiable.

The practical test: after a rename, git am on the archived patch series has to still succeed. If it does not, the rename reached into history and needs to be undone.

Release flow

  1. Branch from main. Never commit a release directly - even though some repositories here allow it.
  2. Run the gates that exist. gradlew check, python3 tools/verify.py --pack packs, python3 -m pytest scripts/tests. Verify prints [verify] OK or a list of findings; a non-empty list is a stop.
  3. Build the artifacts. gradlew dist. Every module jar must contain fabric.mod.json, pack.mcmeta and its own data/ tree - nothing more.
  4. Open a pull request. A ruleset requires one approving review and three named checks; self-approval is rejected on purpose.
  5. Wait for green, then merge. Squash to one commit.
CheckFails when
verify.pya dangling reference, a module calling a module, a module shipping core/internal/, a cycle, a missing pack.mcmeta
test_module_removalany of the 34 packs, built without one sibling, fails to complete load and tick
test_split_guarda module other than core claims a core/internal/ prefix
Datapack guarda pack outside mods/, packs/ or examples/ tries to be buildable

Building this site

The documentation is static HTML with no runtime framework. Two PHP scripts and two Python scripts run at build time and produce nothing that ships:

ToolRunsProduces
tools/build_docs_index.phpphp-cli _site/docs-index.json - every page, its section and its word count
tools/test_php_safety.phpphp-cli exit 0 or a list of violations; never publishes
tools/sitelib.pypython3 the shared page shell - one nav, one footer, one stylesheet
tools/sync_style.pypython3 --check fails if any page's inline style drifted from assets/style.css

No PHP is served. The scripts are CLI-only by construction - each one exits unless PHP_SAPI === 'cli' - and the safety test fails the build if a .php file ever appears in the published tree. Details on PHP tooling.

Backups

Two things are not in git and need to survive a machine loss:

  • World saves containing scoreboard state. A macroEngine install writes its variables into objectives that live in the world. The repository cannot restore them.
  • Built artifacts if a release is pinned somewhere. They are reproducible from a tag, but only if the tag and the toolchain both still exist.

What this project will not claim

Will not claimBecause
A gate makes a bad decision safe. A gate blocks the honest user and inconveniences the other one. Both gates were removed for this reason.
Archived means broken - or means safe. It means unsupported. Those are three different things and only one of them is knowable from the metadata.
Modules are independent by design. They are independent because a test builds each one without its siblings. The design is the seam; the test is the evidence.
A warning is an audit. It reports status, not safety. Confusing the two is what made the gate look reasonable.
Removing a module cannot change behaviour. It changes behaviour by definition - that feature stops. What it cannot do is stop the engine.
