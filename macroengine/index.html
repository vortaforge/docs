macroEngine

A command engine for Minecraft 26.3, split into one core pack and 33 modules. Install all of it, or install the parts you want - the engine does not notice which.

Numbers

  • 34 artifacts: 1 core + 33 modules
  • 1,529 functions
  • 22 hook slots
  • 0 gates

Runtime

  • Minecraft 26.3
  • Fabric Loader 0.20.1
  • Java 25
  • Pack format 121.0

What it is

macroEngine gives a server a command layer: conditional commands, loops, variables, permissions, macros, world edits, text output and a deferred-command queue, all built out of functions that Minecraft itself runs. There is no plugin, no server software fork and no client mod in the path - it is a datapack that happens to ship as Fabric mods.

The distinction matters when something goes wrong. A datapack failing is a refused function call in the log with the exact id that did not resolve. A plugin failing is a stack trace through four layers of an API. The first one can be debugged in a text editor.

The one rule the layout rests on

A pack cannot call another pack. No import, no namespace visibility, no dependency resolution. So the core owns every seam - a function tag - and modules add themselves to a seam instead of calling each other.

Everything else is downstream of that sentence, including why removing a module works and why no module knows what its siblings are called. The long version is on Architecture.

Install

  1. Install Fabric Loader 0.20.1 for Minecraft 26.3, with a Java 25 runtime. A 21 runtime will refuse to start.
  2. Copy the jars you want into mods/. macroengine-core is mandatory; every other jar is optional and each declares the core as a dependency.
  3. Start the server. No config file is required for the core.
  4. Check the log for macroEngine and the module count you installed. A module whose dependency is missing is refused by Fabric at startup rather than loading and failing later.

What to install first

The core alone is a working engine with nothing to do. The modules that make it feel like an engine - by function count, because more functions means more command surface:

  • macroengine-core — 911 functions
  • macroengine-cmd — 123 functions
  • macroengine-player — 58 functions
  • macroengine-lib — 53 functions
  • macroengine-input — 41 functions
  • macroengine-hook — 40 functions

The smallest modules are the narrowest:

  • macroengine-diagnostics — 2 functions
  • macroengine-gamerule — 3 functions
  • macroengine-sound — 3 functions
  • macroengine-tui — 4 functions

Or use it as a data pack

Each jar bundles pack.mcmeta and data/ at its root, so the same content works as a plain datapack in world/datapacks/. What you lose is Fabric's dependency check: a datapack has no depends, so an orphan module loads and its calls vanish silently instead of being refused at startup.

For a single-player world that is acceptable. For a server, install the mods - the refusal at startup is worth having.

What is inside a jar

macroengine-wand.jar
├── fabric.mod.json                 ← what makes it a mod
├── pack.mcmeta                     ← what makes it a datapack
└── data/
    ├── me_wand_module/
    │   └── function/wand/...       ← the module's public surface
    └── me_core_module/
        └── tags/function/hook/
            └── wand_tick.json      ← its claim on a seam

That last file is the whole integration. It is not code that runs; it is a declaration that this module should be in the wand_tick tag. The core never learns the module's name.

What it does not do

  • No client-side anything. environment: "*" is set so the pack loads in single-player, not because there is a HUD.
  • No persistence beyond scoreboards. State lives in scoreboard objectives, which means it lives in the world save and nowhere else.
  • No config GUI. Configuration is a function call.
  • No cross-version support. One Minecraft release at a time.
